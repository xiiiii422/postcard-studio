# 基准卡（Benchmark cards）

用 `scripts/render_benchmarks.py` 复现。基准照片**不在仓库内**（隐私与体积原因），
需要自备；脚本会跳过缺失的卡。

```powershell
# A/B 默认从仓库根目录找 photo-A.img / photo-B.img，R1-R3 从 --real-dir 找
python scripts/render_benchmarks.py --real-dir D:\path\to\photos --out bench
```

## 当前基线（2026-10-18，修复孔洞后）

| 代号 | 类型 | grid | tone 多边形 | EDGE 多边形 | 正面 SVG | 渲染耗时 |
|---|---|---|---|---|---|---|
| A | 风景（雾山） | 640×637 | 212 | 0 | 1272 KB | 2.6 s |
| B | 风景（高对比天空） | 640×853 | 331 | 2 | 1169 KB | 3.6 s |
| R1 | 集市街景（最难） | 800×1206 | 343 | 13 | 1534 KB | 30.0 s |
| R2 | 人物 + 景 | 800×600 | 309 | 23 | 1651 KB | 17.4 s |
| R3 | 双人像 | 800×600 | 406 | 4 | 1185 KB | 5.0 s |

说明：

- `tone` 是颜色层多边形数，`EDGE` 是墨线层，两者分开统计（报告 §5.3 的 212/331/343/309/406
  是 tone 层数字；`sum(len(l[2]))` 会包含 EDGE，两者不要混用）。
- 时间包含 `vectorize_photo` + `front_svg` + `back_svg` + XML 校验；R1 最慢是预期的
  （800×1206 网格 + 多边形自适应重建）。
- 这些数字是确定性的，但会随 Pillow / numpy 版本和照片内容轻微变化；用作回归区间而不是精确值。
- 视觉回归：修复孔洞后五卡的多边形数不变，变化只发生在"深色包住亮部"的孔洞处；
  文件反而略小（每层合并成一条 path）。
